# 台球 3D 物理引擎计划

状态：阶段 P1–P3 已落地。当前权威物理仍是 [physics.ts](../src/domain/pool/physics.ts) 的二维 planck 模拟，但已加入球体三维角速度、完整四元数姿态帧、滑动/滚动摩擦、杆法旋转、球球切向摩擦/甩球、库边旋转、高低杆碰撞旋转传递、袋角几何、跳球、抬杆和扎杆弧线。3D 只负责渲染。本计划讨论后续如何在不破坏房间权威、回放和 AI 的前提下，把物理做得更接近真实台球。

## 结论

优先做 **2.5D 确定性物理 + 完整三维球体旋转**，不直接把整张球桌迁到通用 3D 刚体引擎：

- 球心运动仍然发生在水平台面，二维位置和速度足够描述进球、碰撞和走位。
- 三维只增加球体角速度、旋转姿态、滚动/滑动状态、摩擦和碰撞切向冲量。
- 继续由服务端权威模拟，客户端只播放录像帧，AI 复用同一套模拟。
- 通用 3D 引擎只在评估证明收益大于迁移成本时再考虑。

原因：

- 台球不需要自由落体、堆叠和复杂关节，通用 3D 引擎的大部分能力用不上。
- 全 3D 物理会显著增加确定性、网络同步、回放兼容和 AI 评分成本。
- 真正影响手感的是滚动摩擦、滑动转滚动、旋转、库边反弹、球球摩擦和袋口几何，而不是“有没有第三个维度”。

## 当前基线

已落地：

- 球心二维、服务端 planck、固定 240Hz 步长；每球额外维护三维角速度。
- 滑动摩擦根据接触点速度同时改变线速度和角速度，进入纯滚动后使用滚动阻力。
- 高低杆设置绕横向轴的角速度，侧塞设置绕竖直轴的角速度；不再使用“首次碰撞后追加冲量”的特例。
- 自旋按固定速率衰减；每个采样帧输出球体高度和四元数姿态，3D 直接使用姿态帧。
- 球球碰撞加入切向摩擦/甩球，侧塞会传递切向速度和角速度。
- 库边碰撞加入切向摩擦，侧塞会改变反弹方向。
- 球球和库边碰撞会传递高低杆产生的横向角速度。
- `PoolShot.impacts` 记录球球/库边碰撞时间、类型和强度。
- 袋口使用独立捕获半径和高度判定；库边端部加入共享袋角几何，角袋口宽按球径计算。
- 抬杆输入产生垂直初速度和跳球；高角度配合侧塞产生横向弧线。
- 杆身角度进入击球录像，2D/3D 回放一致。

仍待继续：

- Rapier 等通用 3D 引擎的独立评估。
- 更高精度的袋口碰撞、球体与库边顶部的接触。

## 目标模型

### 球体状态

每个球需要以下权威状态：

| 字段              | 维度        | 说明                                      |
| ----------------- | ----------- | ----------------------------------------- |
| `position`        | 2D          | 台面位置，沿用 `POOL_TABLE` 坐标          |
| `velocity`        | 2D          | 球心线速度                                |
| `angularVelocity` | 3D          | 球体角速度，决定旋转、塞和摩擦            |
| `orientation`     | 四元数      | 渲染球号/花色朝向；由服务端逐帧积分并记录 |
| `rolling`         | 布尔/连续量 | 当前是滑动还是纯滚动                      |
| `pocketed`        | 布尔        | 是否已落袋                                |

台球是实心球，转动惯量按 `I = 2/5 m r²`。球心默认位于半径高度；抬杆输入会给白球垂直初速度，落地后按恢复系数衰减。

### 固定步长

- 服务端固定 240Hz 或 480Hz。
- 每帧物理步长固定，禁止使用真实帧间隔，保证回放和 AI 一致。
- 使用子步或 CCD 处理高速球，避免穿透库边和球。
- 所有随机性来自可记录种子。

### 滚动、滑动和摩擦

真实台球的关键不是简单阻尼，而是接触点速度：

```text
contactVelocity = velocity + angularVelocity × contactOffset
```

- 接触点有相对速度时是滑动，使用滑动摩擦冲量，方向与接触点速度相反。
- 滑动摩擦同时改变线速度和角速度，直到接触点速度接近零。
- 进入纯滚动后改用滚动阻力，减速度明显小于滑动摩擦。
- 侧旋、高低杆和库边摩擦都通过角速度参与接触冲量，而不是单独追加一次冲量。

这能自然产生：

- 低杆回拉、高杆跟进。
- 侧塞改变白球走位和轻微“甩球”。
- 球撞库后的旋转变化。
- 球停止前的最后一段滚动。

### 球球碰撞

两个球接触时：

1. 计算接触法线和切向。
2. 用恢复系数处理法向冲量。
3. 用摩擦系数处理切向冲量，切向相对速度包含双方角速度。
4. 角速度变化由接触点冲量矩产生。
5. 记录碰撞时间、强度、球号和法线，用于音效、回放和调试。

目标不是完全复刻职业台球，而是让直球、定杆、低杆、高杆和侧塞的结果稳定、可解释、可重复。

### 库边

- 库边用胶囊/多边形几何，保留现有袋口开口。
- 法向恢复系数约 0.75–0.9，切向摩擦与球速、旋转相关。
- 侧旋撞库后产生角度和速度变化，而不是简单镜像反射。
- 记录库边碰撞事件，供音效和回放使用。
- 袋口需要独立的袋角和袋口传感器，避免球从袋角“穿模”或贴边卡住。

### 袋口

- 袋口不是无限大的传感器，至少要有袋角和入口宽度。
- 球心进入袋口区域后才判定落袋，避免擦袋被误判。
- 落袋后保留短暂下落动画；权威状态立即标记 `pocketed`。
- 袋口几何与 `POOL_TABLE.pocketRadius` 统一，不在渲染层复制尺寸。

### 出杆

出杆输入：

- 方向。
- 力度。
- 击球点偏移（高低杆/左右塞）。
- 杆身角度 `elevation`。

服务端把击球点偏移转换为角速度，把杆身角度转换为垂直初速度和横向弧线加速度。高力度加高杆身角度形成跳球；侧塞加高杆身角度形成扎杆弧线。

### 数据与回放

- 服务端继续是唯一权威。
- 回放保存击球输入、关键帧和碰撞事件；客户端不重新跑权威物理。
- 关键帧包含球体高度和四元数姿态，3D 不自行重算权威旋转。
- 帧率可以低于物理步率，客户端在帧之间插值位置和姿态。
- 事件流用于击球、碰撞、库边和落袋音效。

## 引擎选择

| 方案                         | 优点                              | 风险                                         | 结论           |
| ---------------------------- | --------------------------------- | -------------------------------------------- | -------------- |
| 继续 planck + 自定义球体状态 | 复用现有确定性和房间/AI；迁移最小 | 需要自己实现旋转、摩擦和库边模型             | **首选**       |
| Rapier 3D                    | 成熟刚体、接触求解、CCD           | WASM 版本一致性、确定性、回放和 AI 迁移成本  | 先做小规模评估 |
| cannon-es / Ammo             | 生态可用                          | 确定性和性能不如专用方案；仍要自己写台球规则 | 不作为首选     |
| 纯客户端 3D 物理             | 视觉自由                          | 客户端分叉、作弊、回放不一致                 | 拒绝           |

Rapier 只有在以下条件全部满足时才考虑迁移：

- 服务端和客户端使用完全相同的 WASM 版本和构建参数。
- 固定步长和确定性测试通过。
- 单杆模拟时间和 AI 候选评分不退化。
- 回放、房间协议和现有 poolShot 结构不需要大规模重写。
- 袋口、库边和旋转手感明显优于 2.5D 自定义模型。

## 迁移阶段

### 阶段 P0：基线测量

- 为当前物理增加可重复的测试数据集：直球、定杆、低杆、高杆、侧塞、库边、袋口和开球。
- 记录停止时间、滚动距离、碰撞角、进袋率和确定性哈希。
- 不改玩法，只建立对照。

### 阶段 P1：球体角速度与滚动

- 增加角速度和姿态。
- 实现滑动摩擦、滚动阻力和滑动转滚动。
- 先在服务端模拟，客户端暂时只渲染位置；姿态通过帧同步。
- 对照：同样的力度和方向，停止时间与走位应更接近真实台球。

### 阶段 P2：碰撞与库边

- 球球切向冲量、旋转摩擦和甩球。
- 库边法向/切向冲量。
- 碰撞事件流。
- 对照：直球、薄球、贴库球和侧塞撞库。

### 阶段 P3：杆法与袋口

- 击球点偏移生成线速度和角速度。
- 高低杆、左右塞和组合塞。
- 袋角几何、擦袋和落袋判定。
- 对照：定杆、跟进、缩杆、侧塞走位和袋口球。

### 阶段 P4：引擎评估（可选）

- 用 Rapier 做独立原型，只跑一组固定测试。
- 与 2.5D 模型比较手感、确定性、性能和回放体积。
- 只有明确胜出才进入迁移；否则保留 2.5D。

## 测试与验收

### 自动化

- 自由滚动距离和停止时间。
- 90 度切球角、薄球角。
- 库边入射/反射角。
- 高杆、低杆、侧塞的白球走位。
- 袋口入口、袋角和擦袋。
- 姿态四元数、抬杆跳球、扎杆弧线。
- 同一输入多次模拟的确定性哈希。
- 回放播放结果与记录结果一致。
- AI 候选评分在固定预算内完成。

### 人工

- 直球定杆、低杆回拉、高杆跟进。
- 侧塞撞库后的白球方向。
- 薄球和贴库球。
- 袋口擦边和下落。
- 连续多杆走位是否可预测。
- 3D 球体滚动方向、球号朝向是否与运动一致。
- 抬杆跳球和侧塞弧线是否符合预期。

## 性能预算

- 单杆权威模拟保持在服务端可接受延迟内，目标不高于当前基线的 150%。
- AI 候选评分在现有 Worker 预算内完成。
- 单杆回放体积增长可控；姿态帧按需降采样。
- 客户端渲染不重新模拟权威物理。

## 已确认

1. 继续使用 2.5D 权威物理 + 三维旋转，不直接迁移完整 3D 刚体引擎。
2. 保留跳球、扎杆和 masse；由杆身角度、力度和侧塞共同决定。
3. 球体姿态进入网络帧，客户端只插值，不重算权威旋转。
4. 袋口使用共享袋角几何、捕获半径和高度判定，不使用无几何传感器。
5. UI 使用高低杆、左右塞和杆身角度按钮；击球点面板留待后续。
