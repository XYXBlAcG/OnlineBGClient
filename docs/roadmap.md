# 后续规划

现有功能与实现入口见 [架构](architecture.md)；实际交付和验证限制见 [验证](verification.md)。本页仅记录尚待实施的产品决策。

| 阶段 | 范围 |
| --- | --- |
| 当前交付验证 | Windows 11 实机安装、高 DPI 与窗口交互；两台设备在不同网络完成邀请、对局、聊天、恢复和退出 |
| 手机实机验证 | iOS Safari、Android Chrome 的触屏、锁屏、输入法、Wi-Fi／移动数据切换和多设备联机 |
| 手机与聚会体验 | [待审核功能与验收](product-next-plan.md)，暂缓实施 |
| 独立插件 | 游戏、策略、主题独立安装；完整性校验、资源路径、加载卸载、被存档引用时的删除约束；沿用内置契约 |
| 斗地主策略 | 独立策略内核、透明决策与审核；先验证规则及策略收益，再选择模型与 NVIDIA／Windows 11 推理方式 |
| GPU 搜索／推理 | 当前 CPU 策略之外的批量算法或模型、收益评测、Windows 11／RTX 实机验证；提供可用后端后再开放设置 |
| 发布渠道 | 构建与 Release 入口见 [游戏与发布](game-ai-release-plan.md)；签名、自动更新与公开分发待审核 |
| 其他平台 | macOS Intel、Windows ARM、Linux、Android、iOS 工具链、交互与生命周期验证 |
| 多人扩展 | 语音与房主迁移另行设计；不实施云端部署 |

独立扩展复用公共房间、通信和命令入口，游戏保留专属界面。缺少匹配组件时明确拒绝启动，不替换规则。主题仅改变视觉，不修改游戏权限或状态。

## 自动更新方案（待实施）

采用 [Tauri 官方更新插件](https://v2.tauri.app/plugin/updater/) 的签名产物与更新清单。桌面启动后后台检查，每 24 小时最多自动检查一次；设置提供手动检查和自动检查开关。更新提示不打断对局，下载显示进度；安装前保存对局，待用户确认后重启。检查失败保持客户端可用，手动检查展示失败原因。

代码仓库维持私有。正式实施前选择安装包与更新清单的分发入口：独立的公开发布仓库、静态文件服务，或带用户授权的下载服务；不在客户端内置私有仓库凭证。Windows 与 macOS 分别生成签名更新产物，稳定版和预览版采用独立渠道；浏览器手机端使用房主服务版本。

验收包含无更新、有更新、签名错误、下载中断、离线、对局中延期安装和重启后恢复。当前没有安装更新插件或启用自动检查。
