# 客户端房间连麦方案

状态：方案已确认，首版接入代码等待客户端审核；运行、配置与当前验证边界见[客户端语音](client-voice.md)。不提交、不推送。肉鸽 Demo 暂停扩展。

## 产品范围

第一版支持 macOS、Windows 桌面客户端的同房间语音，最多 8 名真人同时加入，包含仅开服务的房主。AI 不占语音名额。手机和桌面浏览器仍可玩游戏、发送消息，但不能加入、收听或发送语音；未来手机原生客户端另行设计。

加入房间不自动开麦。点击「加入语音」后先选择设备并明确确认，默认静音入会，可以只听。首次需要麦克风时才触发系统授权。权限拒绝不影响游戏，也不妨碍仅收听。

语音属于房间，不属于某款游戏：结束对局、配置下一局、切换游戏、收起聊天与进入专注模式不退出语音；离开房间、被移除或退出应用时释放通话。第一版不增加录音、转写、视频、屏幕共享、变声、跨房间通话或队伍私密频道。

## 推荐技术与部署

采用 **LiveKit Cloud + 官方客户端 SDK + WebRTC 音频**。Tauri 保持现有 React 和原生窗口体系，第一版使用 WebView 音频采集与播放；权限和应用生命周期由原生层管理。不自建编解码器、回声消除或全员 P2P 连接网格。

| 路径 | 职责 |
| --- | --- |
| 原有 Cloudflare Tunnel → 房主 Node 服务 | 继续传输牌局、聊天、房间身份与语音授权请求 |
| 桌面客户端 → LiveKit SFU／TURN | 实际语音传输，与牌局 WebSocket 分离 |
| 房主服务 → LiveKit 管理接口 | 为有效房间成员签发语音权限，移除成员，关闭频道 |

现有 `cloudflared --url http://…` 公开 HTTP 服务不等于 WebRTC 媒体中继。Cloudflare Realtime SFU／TURN 是另一组服务，不能把当前隧道当成已经具备的连麦能力。依据：[Tunnel 协议](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/routing-to-tunnel/protocols/)、[Realtime 架构](https://developers.cloudflare.com/realtime/sfu/)。

第一版由房主一次性配置自己的 LiveKit 项目地址和服务凭据，朋友只安装客户端，不需要注册语音服务。凭据保存在房主本机原生凭据存储，由本机服务使用，不打进客户端安装包、邀请链接或发送给玩家。不部署云端游戏服务器，也不另建公共令牌服务。未来所有人都免配置，需要独立的统一授权服务，属于另一项部署决策。

SDK 已提供轨道、设备、订阅和重连能力；服务凭据签发令牌必须在后端进行，权限限定房间、成员和音频轨道。[媒体能力](https://docs.livekit.io/transport/media/)、[授权](https://docs.livekit.io/frontends/build/authentication/)。

浏览器版不加载语音模块、不请求语音令牌；原生入口通过 Tauri 命令取得当前客户端会话授权。后端仍检查真实房间成员与语音权限，不以 User-Agent、请求 Origin 或一个 `isDesktop` 字段代替身份认证。客户端专属是本产品支持边界，不将桌面壳标志描述为不可伪造的设备证明。

## 方案对比与成本依据

以下服务资料核对日期为 2026-10-25。价格和额度来自官方页面；流量是按假设计算的估算，不是本项目实测。

| 方案 | 取舍 |
| --- | --- |
| LiveKit Cloud，推荐首版 | 成熟房间 SDK，设备、发言状态与断线处理复用较多；需要房主配置项目 |
| Cloudflare Realtime SFU／TURN | 流量额度大；低层 SFU API 需要自行管理会话、轨道发现、订阅和更新顺序，首版开发维护范围更大 |
| 自建 LiveKit | 能沿用同一套 LiveKit 客户端，但需要公网媒体服务器与开放端口；不适合当前只靠临时 HTTP 隧道的开房方案 |
| 全员 P2P + TURN | 仍需 TURN 才能覆盖复杂网络；8 人房间形成 28 对连接，连接恢复和每人上传负担更高，首版不采用 |

LiveKit 当前免费档列出每月 5,000 WebRTC 参与者分钟、50 GB 下行流量。4 人通话 1 小时消耗 240 参与者分钟；仅按分钟额度计算为约 20.8 小时/月，8 人为约 10.4 小时/月，实际还受流量与其他额度限制。不要套用其 AI Agent 的分钟报价到普通玩家语音。[官方价格](https://livekit.com/pricing)。

Cloudflare Realtime 当前 SFU 与 TURN 共用每月前 1,000 GB 免费出站额度，超出为 $0.05/GB。[官方价格](https://developers.cloudflare.com/realtime/sfu/platform/pricing/)。假设每人持续发送 24 kbit/s 的单声道编码音频、所有人订阅其他人，媒体载荷出站量为 `人数 × (人数−1) × 24,000 × 秒数 ÷ 8`：

| 同时在线 | 每人上传载荷 | 每人下载载荷 | 1 小时 SFU 出站载荷 |
| --- | --- | --- | --- |
| 4 人 | 24 kbit/s | 72 kbit/s | 约 0.130 GB |
| 8 人 | 24 kbit/s | 168 kbit/s | 约 0.605 GB |

这些值未包含 RTP／UDP／加密头、重传、TURN 和其他协议开销，也没有扣除静音省流；实际以服务账单与 SDK 统计为准。首版以 24 kbit/s 为初始语音配置，清晰度及网络表现需要真人通话验收。

## 界面放置

沿用当前界面控件、主题和原生辅助窗口机制。[静态布局预览](../.tmp/docs/voice-plan-preview.html)使用现有项目样式和牌桌截图；其中在线人数、姓名、信号状态均为示意，不是运行数据。

| 位置 | 内容与行为 |
| --- | --- |
| 房间工具栏，聊天入口旁 | 未加入显示「语音」；加入后显示「语音 4」和本人麦克风状态。点击展开语音控制，不在工具栏铺开成员列表 |
| 聊天侧栏底部 | 文字输入区下方固定约 76–96 px 的紧凑语音栏：连接状态、人数、静音、耳机静音、设备、离开。消息列表只使用剩余空间，输入框和语音栏不重叠 |
| 聊天侧栏内展开区 | 成员头像、完整姓名、说话指示、本人静音、房主禁言、个人音量。收起后只保留语音栏；不在牌桌上常驻完整名单 |
| 聊天关闭／专注模式 | 保留工具栏紧凑控件，可直接静音；不新增遮住手牌的悬浮球。窄窗口优先保留静音和展开，其余放入菜单 |
| 独立原生聊天窗口 | 显示同一个语音会话的状态与控制；关闭窗口只是收起界面，不断开通话，不启动第二次采集 |
| 设置 → 声音与语音 | 麦克风、扬声器、输入检测、音量、自由说话／按键说话、快捷键、入会静音、游戏音效压低选项 |
| 手机／桌面浏览器 | 不挤占房间工具栏，仅在房间菜单中说明「连麦需使用客户端」 |

说话头像用稳定外圈加小型音量指示，静音、仅收听、重连有不同图标和文字；不反复跳动、不闪全屏横幅。界面动画关闭时保留静态状态。成员姓名不因音量图标被挤成竖排。

新成员加入不会自动抢占中央画面或强迫任何人开麦。设备选择与音量调整复用原生辅助窗口；系统权限弹窗由操作系统显示。第一版不加第二套独立语音窗口。

## 通话操作与状态

- 默认自由说话，提供按键说话。快捷键接入现有命令注册，可改键，避开游戏和聊天输入；第一版按键说话只在客户端获得焦点时响应，失焦立即停止发送，避免卡住开麦。跨应用全局按键放到后续。
- 本人「麦克风静音」仅停止发送；「耳机静音」停止接收播放并同时停止发送，解除后恢复之前的麦克风设置，但房主禁言仍优先。
- 每位玩家可独立调低某人的音量或本地屏蔽；只影响自己。房主可禁止发言或移出频道，但不能替玩家打开麦克风，不能覆盖本人静音。
- 提供输入电平和手动耳返测试，默认不耳返；自动回声消除、降噪使用 WebRTC 基础处理，首版不引入 GPU 降噪或收费增强模型。[SDK 音频处理](https://docs.livekit.io/transport/media/)。
- 输入设备拔出先停发并提示设备变化，不悄悄切到另一个麦克风。重新选择后由用户确认开麦。输出设备优先跟随系统；WebView 未提供输出切换接口的平台引导到系统声音设置，不显示失效下拉框。
- 状态明确区分：未配置、未加入、连接中、仅收听、已静音、正在发言、重连中、权限拒绝、设备不可用、服务不可达。无声时给出对应原因，不统一显示 `error`。
- 最小化和隐藏窗口保留同一语音会话；完全退出、电脑休眠及断网不能持续通话。唤醒后重新连接，保留本人静音和房主限制。房间服务失联时暂停发送，权威成员资格确认后恢复，不让被移除的人靠旧媒体连接继续说话。
- 所有客户端都能退出语音而继续游戏。频道失败不阻塞出牌、游戏同步或 AI。

## 结构与复用入口

| 领域 | 现有入口与设计方向 |
| --- | --- |
| 房间身份和主持权限 | [房间](../src/domain/room.ts)、[网关](../src/domain/gateway.ts)、[协议](../src/domain/protocol.ts)；语音成员绑定稳定身份，不绑定席位索引、昵称或当前游戏 |
| 语音权威 | 房主服务增加单独的成员授权与频道管理模块；令牌签发、撤销和房间关闭只有这一条写入口，实际移除成员要通知 SFU，不能仅等待令牌过期 |
| 客户端会话 | 在应用根部建立唯一 VoiceSession，独立于牌桌组件、聊天组件与游戏路由；只向控件提供状态和命令，不把音频对象放入牌局快照 |
| 多窗口 | [窗口契约](../src/client/native/contract.ts)、[原生桥](../src/client/native/windows.ts)、[原生窗口](../src-tauri/src/windows.rs)；主会话唯一拥有麦克风和远端播放，其他窗口只传命令与状态 |
| 声音与控制 | [聊天](../src/client/ChatPanel.tsx)、[工具栏](../src/client/RoomToolbar.tsx)、[设置](../src/client/Settings.tsx)、[命令](../src/client/commands.ts)、[音效](../src/client/sound.ts)；语音音量不与游戏音效共用静音开关 |
| 原生生命周期 | [桌面](../src-tauri/src/desktop.rs)、[应用](../src-tauri/src/lib.rs)；连麦参与关闭窗口／退出判断，即使该电脑不运行房间服务也生效 |
| 权限 | macOS 增加麦克风使用说明与相应打包权限，核对 WKWebView 的采集来源；Windows 核对 WebView2 麦克风授权及系统隐私设置。仅允许本机应用来源，原站游戏 iframe 不取得麦克风权限 |

macOS 与 Windows 的 WebView 均提供媒体权限机制，但当前仓库还没有语音接入，不能把官方 API 支持当作本应用已经验证通过。[Apple 权限接口](https://developer.apple.com/documentation/webkit/wkuidelegate/webview(_:requestmediacapturepermissionfor:initiatedbyframe:type:decisionhandler:))、[Microsoft 权限类型](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/winrt/microsoft_web_webview2_core/corewebview2permissionkind)。

第一版依赖 SDK 的回声消除与网络适配；音量显示更新限制在每秒约 10 次，只更新语音成员区域。统计仅在面板展开时低频采样，不采集录音，不把每帧音量写进数据库或回放。语音授权与临时在线状态不进入游戏回放；持久化只保存本机设备和偏好。

## 实施顺序与验收

1. **双端原生样板**：先在现有 Tauri 的 macOS 与 Windows 包中完成两台客户端互通，验证系统授权、收发、耳机、最小化、主窗口隐藏、辅助窗口关闭，以及 WebView 后台生命周期。若打包 WebView 在目标系统未通过采集或后台验收，先解决平台实现，不发布空语音入口。
2. **房间贯通**：接入身份、后端令牌、最多 8 人、主持禁言、移除、离房清理、同房间换游戏保持通话；覆盖服务电脑单独加入和浏览器不可用入口。
3. **设备与界面**：紧凑栏、成员面板、设备测试、按键说话、快捷键、主题、低高度和专注模式；本轮预览只确定放置，不提前实现。
4. **真实网络验证**：至少家庭宽带与手机热点两种网络，两端跨网；再测 4 人与 8 人连续 30 分钟。采集加入成功次数、首个音频到达时间、SDK RTT／抖动／丢包、断线恢复、CPU 与内存变化。RTT 不冒充端到端听感延迟；没有实际采集的数据不填写为结果。
5. **审核交付**：定向单元与跨层测试覆盖重复加入、权限变化、撤销后踢出、重连后禁言、主辅窗口单实例、退出释放；真人验收双方音频、回声、设备和后台行为。界面与实际通话由用户手动操作，提供步骤和预期，不操作用户电脑。审核前不提交或推送。

网络验收目标：正常网络下每组 20 次加入至少成功 19 次，加入到收到首个远端音频的 P95 不超过 5 秒；4／8 人各持续 30 分钟无崩溃、无重复采集和重复播放；网络恢复后 10 秒内恢复或明确显示失败并提供重试。这些是拟定门槛，不是当前已取得的测量结果。中国大陆实际线路表现必须在目标网络测量，不能用厂商全球覆盖宣传替代。

LiveKit 账户与使用额度由房主控制；尚无项目时先审核本机客户端，不创建账户、部署云端服务或产生费用。
