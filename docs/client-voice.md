# 客户端房间语音

macOS 与 Windows 客户端使用独立语音通道；浏览器不提供连麦。当前已完成接入代码，真实双端语音与界面由用户手动验收。没有配置 LiveKit 项目时仍可审核界面、测试本机输入，不会建立公网语音通话。功能范围与后续网络验收目标见[方案](client-voice-plan.md)。

变声、设备输出、快捷键与横幅的使用和验收见 [体验入口](voice-effects-and-input.md)。

## 找到入口

大厅「快速上手」旁的「连麦设置」直接进入声音与语音；设置顶部提供房主配置与加入者的分步引导。没有配置时，房主配置表单默认展开。房间内「聊天 → 房间语音 → 设备与连麦设置」也可进入；未配置的房主可直接点击「配置房主语音」。收起大厅引导后，连麦快捷入口仍保留。

## 手动审核

客户端安装见 [软件更新](updating.md)，定向检查入口见 [验证](verification.md)。实际连麦由用户验收。

1. 打开「设置 → 声音与语音」。检查浅色／深色、窗口缩窄、下拉菜单、滑杆及输入电平的布局。麦克风授权前设备名称可能不完整，属于系统限制；点击刷新设备重新枚举。
2. 佩戴耳机，点击「测试麦克风」，由你确认系统权限，讲话时检查输入电平。耳返默认关闭，可手动开启后比较。点击停止，或关闭设置窗口，确认系统麦克风使用指示结束。拒绝权限时应显示操作建议，不影响牌局。
3. 创建公网房间，打开聊天，检查底部语音栏和工具栏语音入口。尚未配置服务时，加入按钮不可用，设备入口可用。开房与真人游戏应正常工作；本地对局只说明需要联机房间。
4. 收起／展开聊天，调整侧栏宽度并进入专注模式，检查控件不遮住手牌。窄窗口打开原生聊天辅助窗口时，界面仍共享主会话。
5. 浏览器打开邀请链接，继续正常聊天和游戏，不出现语音收发控件。

这里的步骤需要用户亲自操作。类型检查、静态渲染、HTTP 请求和打包通过不能代替这些验收。

## 配置与实际连麦

在 [LiveKit Cloud](https://cloud.livekit.io/) 创建或进入项目，从 Settings → Keys 创建 API Key 和 Secret，并复制项目的 `wss://…livekit.cloud` 地址；这是媒体服务地址，不是控制台网页链接。入口见 [LiveKit 官方说明](https://community.livekit.io/t/where-to-find-the-livekit-api-key-and-secret/92)。无需部署语音 Agent。

由开房电脑在「设置 → 声音与语音 → 房主语音服务配置」填写自己的 LiveKit 项目地址、API Key 与 Secret。Secret 仅在本机输入；保存到系统凭据存储，不从读取配置接口返回。已有 Secret 留空可保留，另有清除凭据入口。

保存后在下一次启动房间服务时生效。已有房间不会被自动重启；需关闭当前房间后重新创建，再让其他客户端加入。朋友不需要填写项目配置。不创建统一云端游戏服务或公共账号。

1. 两台客户端进入同一房间，各自点击「加入语音」并确认静音加入。先核对成员，再分别主动开麦，确认双方收听和发言。第一次开麦或输入测试才申请系统麦克风权限。
2. 麦克风静音只停止本人发送；耳机静音停止收听并暂停发送，解除后恢复之前的麦克风选择。个人音量只影响自己。输出切换接口不可用的平台跟随系统输出，在系统声音设置中切换。
3. 房主可禁言、允许发言、移出频道和重新允许加入。允许发言不替对方开麦；对方仍需自己操作。语音身份随房间成员保持，不依赖当前游戏的席位位置。
4. 「说话方式」选择按键说话后，先开启麦克风作为允许发送，再按住对应快捷键发送。按键在「快捷键 → 按住说话」修改；未聚焦客户端、输入文字、松键或窗口失焦时停止按键发送。第一版不接管其他应用的全局按键。
5. 结束游戏、同房间切换游戏、收起聊天、关闭聊天辅助窗口、最小化／隐藏主窗口后分别检查通话。离开房间、被移除或完全退出客户端后应释放语音。电脑休眠与断网不持续传输；恢复后重新核对房间身份和禁言状态。
6. 拔出麦克风或更换输入设备后应暂停发送并要求重新确认开麦。不要在通话中启动独立输入测试；请先退出语音，避免第二次采集。

跨网络的实际测量项目和验收门槛见[方案](client-voice-plan.md#实施顺序与验收)。当前没有真实跨网音质、时延、成功率或 Windows WebView2 的实测结论。

若加入按钮不可用，先确认房主已保存配置并重新创建房间；填写项目控制台网页地址不能代替 wss 项目地址。若没有声音，先检查默认静音、耳机静音、语音总音量、系统权限和输出设备。
