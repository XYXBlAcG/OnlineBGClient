# 秘塔远征：合作卡牌肉鸽方案

状态：完整游戏方案待审核；[本地战斗 Demo](expedition-demo.md)已实现独立验证入口，尚未接入大厅与联机。不提交或推送。

## 方向与范围

在大厅中增加独立游戏「秘塔远征」（暂名），支持 1–4 个角色席位，真人和 AI 可混合。每人控制自己的角色与牌库，共享路线和战斗目标。采用原创职业、卡牌、敌人和事件，参考卡牌肉鸽的构筑、敌方意图、遗物组合与冒险成长体验。

参考依据：[Mega Crit 的《Slay the Spire 2》官方商店介绍](https://store.steampowered.com/app/2868840/Slay_the_Spire_2/)。其最多四人合作、多人专属卡牌和团队协同是参考方向；本方案的具体规则均为拟定设计，不代表原作规则。

首版交付一章可完整通关的冒险，单局以约 30–45 分钟为调优目标，不承诺尚未试玩验证的时长。保留单人体验，不强制加入 AI；四人可以选择重复职业。

| 内容 | 首章目标 |
| --- | --- |
| 职业 | 铁卫：格挡、保护与反击；游侠：连击、弃牌与标记；炼术师：持续伤害、削弱与支援 |
| 卡牌 | 各职业 18 种，公共牌 12 种，共 66 种；职业卡含基础牌，升级形态不重复计数 |
| 成长物品 | 18 种遗物、8 种药水；支持卡牌升级、移除和消耗牌 |
| 遭遇 | 8 种普通敌人、3 种精英、2 种章末 Boss，组合成不同遭遇 |
| 地图 | 12 层分叉路线；普通战、精英、事件、商店、营地、宝箱与章末 Boss |
| 事件 | 10 种，有收益与代价，并存在适合不同构筑的选择 |
| 难度 | 故事、标准、挑战；与 AI 队友的简单、普通、困难分开设置 |
| 现有能力 | 链接联机、电脑只开服务、手机加入、聊天与头像互动、快捷键、主题与动效开关 |

三章长线、更多职业、无尽模式、创意工坊和 GPU 模型推理留待首章体验验证后设计。本轮不新增云端部署或语音。

## 冒险与战斗

完整循环为：选择职业 → 路线投票 → 遭遇 → 各自奖励与构筑 → 队伍准备 → 下一节点 → Boss → 通关或失败。地图生成需验证起终点可达、分叉合法、关键恢复节点可达；不保证每次错误决策都能获胜。

战斗使用团队行动阶段：所有未结束行动的存活队员都可以出牌，服务器按接收顺序逐个原子结算。各人拥有独立能量、手牌、生命、格挡与状态；默认每轮三能量、抽五张，具体数值在实现后的内容配置中维护。全员结束行动后，依次结算敌人阶段，再开始新一轮。

- 敌人意图提前显示攻击、次数、目标及状态效果；伤害预览使用同一规则计算，并随已确认局面更新。
- 先选择卡牌，再选择敌人或队友；不可用目标说明原因。目标刚被队友击败时，拒绝该动作并保留可重新选择的卡牌，不扣能量，不偷偷换目标。
- 默认无回合倒计时。玩家结束行动后，在队伍尚未进入敌方阶段前可取消结束；阶段推进后不能撤回。
- 队友手牌可以主动查看，主界面仅展示自己的手牌。牌库顺序、尚未发生的随机结果和未来奖励不公开。
- 倒地角色当场停止行动；队伍获胜后以少量生命恢复，避免一位玩家长期旁观。全队倒地判负。复活比例和少量救援效果在平衡配置中统一维护。
- 敌人的血量、攻击分配及协作机制共同随队伍规模调整，不仅把血量乘人数。首版同屏最多三个敌人。
- 卡牌、遗物和状态的触发使用确定顺序的效果队列；不依赖动画完成回调推进规则。

合作应体现在可用的配合上，例如铁卫替游侠承担伤害，游侠给精英施加标记，炼术师利用标记增强持续伤害或支援。队友能标记“准备攻击此目标”或“需要保护”；标记是沟通提示，不锁定其他玩家的操作。

## 奖励、路线与人员管理

个人奖励独立生成，每人三选一或跳过，避免抢卡；金币与常规商店库存按个人管理。共享遗物、路线和团队事件先投票，所有人确认后推进；平票由轮换的领队在平票选项中决定，不固定由房主决定全部内容。个人营地和奖励选择可以同时进行。

冒险开始后固定角色槽位数及其构筑。朋友可以在地图、营地等安全节点接管现有 AI 或离席角色，不在战斗中增减角色和重新缩放敌人数值。离席后暂停或托管由明确设置决定，不自动代出牌。

断线重连恢复原角色；正在处理的动作按唯一编号去重。默认暂停等待离线真人，不趁玩家切后台结算敌人攻击；经房主与相关玩家授权后，可明确切换 AI 托管。

## 长局存档与回放

冒险拥有独立于临时公网地址和房间编号的 `runId`。房主电脑保存权威冒险，本地模式保存到本机。先复用现有 SQLite、IndexedDB 和房间恢复机制，在同一存储层增加冒险存档，不另建数据库或在线服务。

- 已确认动作持续保存；节点切换、奖励完成和战斗结束建立检查点。
- 区分“暂存并离开”和“放弃冒险”。房间切换到其他游戏前保留冒险；放弃需确认，不将旧冒险绑定为新局状态。
- 重新创建房间后可继续冒险并生成新邀请，保留职业、牌库、地图和遗物。恢复角色控制需要明确席位分配，不依据昵称自动认领。
- 存档包含规则版本和内容版本；不兼容时明确提示并保留原文件，不改用其他规则打开。
- 回放沿用已有播放、暂停和倍速，但改为按需还原局面与检查点跳转，不为整场冒险一次性克隆所有历史状态。
- 活跃冒险与可清理的历史回放分开管理。清理回放不会删除进行中的冒险；删除冒险有独立入口和确认。

## AI 与性能

怪物使用可解释的行为模式和带条件的意图选择，不需要大模型。AI 队友分为：简单——合法动作和基础攻防；普通——有限搜索本轮出牌顺序及团队收益；困难——扩大候选和预算，估计下一轮生存、关键击杀与构筑协同。

AI 的购牌、奖励、升级、移除、药水和路线选择也必须能完成，不能只有战斗 AI。AI 只能读取与真人相同的队伍可见信息，模拟未来抽牌时从未知牌序抽样，不能查看权威牌库或未来随机结果。审核记录说明防止了多少伤害、为何保护队友及为何保留药水；关闭审核时不生成解释和审计副本。

复用 CPU Worker、线程池、取消、难度预算和计算统计。局面变化后废弃旧搜索结果，只执行重新校验后的决策。先基准测试采样、效果结算、序列化和渲染的耗时，再分配并行任务；没有实测收益的 GPU 后端不显示为可用。

卡牌与头像使用轻量 DOM，场景和攻击路径用 SVG，动效复用现有事件层。规则确认后立即更新数值，视觉队列独立播放；收起详细日志，不为每一帧重新计算全部卡牌。界面动画和增强游戏动画继续分开控制，基础动效、增强动效和减少动态效果都要可读。

## 界面与交互

桌面采用：顶部战斗阶段与资源，中间敌人和队伍角色，底部自己的手牌和结束行动。地图、遗物、牌库与详细日志按需展开，聊天使用既有侧栏；不恢复自由布局编辑和额外玩家板块。

- 敌人血条、意图和受击目标始终清楚；伤害、格挡、治疗有不同颜色与图形，不只靠颜色区分。
- 头像保持独立圆形尺寸，姓名和数值放在旁边；角色特效落在场景角色上。
- 手机横屏优先展示完整战斗场景、手牌和聊天入口；竖屏采用紧凑敌人行和可横向浏览手牌，详情用现有浮层，不让浮层永久占据中央。
- 默认点击选牌、点击目标确认，不强迫拖拽。桌面支持数字键选牌、目标切换、确认、取消和结束行动；输入聊天时不触发牌桌快捷键，并允许改键。
- 动画包含卡牌飞向目标、命中、护盾吸收、治疗、状态叠加、抽弃牌和精英／Boss 登场。增强动效可跳过等待、合并连续跳字，不妨碍再次操作或遮住意图。
- 新手引导按当前战斗实际卡牌和敌人定位，解释本次可选目标、敌方意图与合作操作；可以关闭。

## 分阶段交付与验收

1. 战斗样板：复用现有组件搭建真实页面，用两个职业、少量卡牌和一个敌人跑通选择、出牌、伤害、格挡与敌方意图；检查桌面、低高度与手机横竖屏截图。它是开发检查点，不单独冒充完整游戏。
2. 战斗与合作：完成触发队列、状态、药水、倒地、多人行动窗口、结束确认，以及并发提交、失效目标、去重与重连检查。
3. 首章闭环：补齐三个职业和目标内容量、路线、奖励、商店、升级与遗物；实现保存、继续、离席接管与通关／失败。
4. AI 与体验：三档 AI 完成战斗和冒险决策，基准与透明审核通过后，加入完整动效、实际局面引导和回放。
5. 交付审核：规则与跨层测试、真实 HTTP/WebSocket 和 Worker 检查通过；按授权范围进行隔离浏览器实际操作与逐轮截图，确认样式后生成 `.app`。不操作用户桌面，原生 WebView、Windows 与真机触控仍由用户验收；未获新的提交授权不 commit、不 push。

关键测试应先于实现：伤害／格挡／状态顺序，抽牌与洗牌，卡牌和能量守恒，遗物连锁，倒地与终局，地图可达，个人奖励隔离，商店扣款原子性，多人同时结束行动，跨阶段旧动作，断线与托管切换，检查点恢复和回放一致性，以及 AI 不读取隐藏牌序。进行定向测试，不在开发过程中反复运行全量测试。

首版通过标准是：1–4 个角色能走完整章；两名真人同时操作不靠反复重试；关闭服务后能继续冒险；手机能选牌和目标；正常及低高度布局无头像拉伸、卡牌撑高、手牌遮挡；AI 不越权、不偷看，审核开关真实生效。
