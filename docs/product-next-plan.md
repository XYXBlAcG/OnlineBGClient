# 后续体验功能（待审核）

本页功能均暂不实施。已交付能力统一见 [架构](architecture.md)，AI 接入独立见 [卡坦岛方案](catan-ai-plan.md)。不增加云端部署或语音。

远程启动电脑与无人值守服务的唯一方案见 [手机远程开房](remote-host-plan.md)，不在本页重复。手机操作延迟已有基础优化，后续以真实设备和网络测量确定瓶颈，不通过固定延迟、重复请求或降低权威校验掩盖问题。

| 优先级 | 痛点与拟定功能 | 验收规则 |
| --- | --- | --- |
| P0 | 手机临时切后台导致整桌暂停：可配置断线宽限、前台主动补齐状态与恢复提示 | 断线可见；宽限期间按房主策略继续其他合法阶段，到期明确暂停；离线玩家不被偷偷代出牌；旧版本动作拒绝并刷新，不重复提交 |
| P0 | 点了不知是否生效：按操作展示「已选择／发送中／已确认／连接中断」，诊断延迟来源 | 已选择、可取消的本地选择即时响应；出牌只在权威确认后生效；不用假出牌动画伪造确认；区分往返、服务排队、AI 与本地渲染，记录 P50／P95 和重复请求率，本地选择反馈目标不超过 100 ms；诊断不含私人手牌或恢复凭据 |
| P0 | 触屏目标太小、牌桌频繁上下滚动：各游戏触屏操作适配、手牌放大、就近动作条 | 保留完整原牌桌；仅对需要的游戏提供手牌放大层；横竖屏保持选择；手机键盘打开不遮发送按钮；缩放后的棋格与卡坦岛 SVG 命中准确，不重新引入自由布局编辑 |
| P1 | 新玩家不知道下一步：合法目标高亮、阶段提示、就地规则说明 | 来源是现有合法动作与规则；能定位具体卡牌、棋格与建造点；无合法目标解释当前阶段；不泄露隐藏信息，可关闭提示 |
| P1 | 玩家临时有事：离席与 AI 托管 | 仅支持已有策略的游戏；由本人或明确授权的房主开启；切换控制在决策边界完成；离线不默认等同托管；恢复后操作不会和 AI 同时生效 |
| P1 | 经常使用相同配置：聚会模板、常用电脑和继续上次房间 | 模板保存游戏、人类／AI、名称、难度与节奏；破坏性调整需确认；复用既有房间；未实现的 AI 不可选；不会将其他用户恢复身份写入模板 |
| P1 | 临时邀请变化后找不到房间：配对控制页的「继续房间」与新邀请、一次性席位恢复码 | 对局与席位身份独立于隧道地址；新入口验证版本与身份；恢复替换旧连接；邀请和管理权限分离 |
| P1 | 长局争议或学习困难：回放时间轴、事件筛选、书签和导出 | 扩展已有播放／暂停／倍速；书签关联事件编号，跳转还原确定性局面；私人视角遵守权限；版本不匹配明确拒绝；回放界面保持只读 |
| P2 | 大屏公共牌桌与独立观战身份 | 观战不占席位、不触发暂停；电视不显示私人手牌；房主控制聊天和加入权限；手机操作与公共视角同步 |
| P2 | 游戏规则和房规不好查：规则版本、当前房规摘要与快捷提示 | 配置只来自游戏插件已声明的能力；不支持的房规不伪造；开局前大家看见当前配置；动作仍走统一校验 |
| P2 | 性能设置难选：设备检测、可中止基准与自动预算建议 | 区分前端渲染、CPU 搜索与网络；从现有计算统计派生建议；有电池／安静与性能预设；没实现 GPU 后端就不显示可用；基准不默认启动或在对局中抢占算力 |

实施顺序建议：远程方案 A／B／C 与 P0 一起完成手机闭环，再评审 P1；P2 单独选择。每项先做真实设备基线，再按涉及范围进行单元与联机回归，不以浏览器模拟替代 iOS／Android 及 Windows 11 实机验证。自动更新仍按 [更新方案](roadmap.md#自动更新方案待实施) 另行实施。

备用电脑接管需要转移权威服务和存档，并重新建立公网入口；手机浏览器不能直接承担当前房间服务。若需要这项能力，应单独设计和验证，不用浏览器房主权限替代服务迁移。
