# 社交符号与差异化计划

状态：待审核。本页定义产品方向、社交符号和验证指标，不重复已有实现细节。现有社交入口见 [社交体验](social-experience-plan.md)、[房间语音](client-voice.md)、[多人房间](multiplayer-room-experience.md)、[舞台与 LLM](social-stage-llm-plan.md)。

## 结论

我们不是要做一个“更好的微信”或“更便宜的 Discord”。

我们的定位应该是：**牌桌会回应的联机桌游客户端**。

微信负责约人、日常聊天和离线通知；我们负责“从进入房间到这一局结束”的完整体验。差异化不来自聊天功能更多，而来自聊天、语音、表情、成就、舞台和游戏状态之间的绑定。

## 为什么不是直接用微信或 Discord

| 能力       | 微信 / Discord             | 我们                                          |
| ---------- | -------------------------- | --------------------------------------------- |
| 进入方式   | 加好友、建群、发会议号     | 一条邀请链接直接进入房间                      |
| 游戏状态   | 不知道谁轮到、谁在思考     | 知道座位、回合、候选动作、暂停、离线、AI 托管 |
| 消息语义   | 纯文本、图片、语音         | 快捷短语、表情、互动、投票、竞猜、成就广播    |
| 语音与牌桌 | 语音是独立频道             | 发言者、座位、回合、观众、房主权限在同一房间  |
| 成就与回放 | 需要手动截图、转发         | 成就自动进入房间消息和舞台，回放可追溯        |
| 观众       | 只能旁听或看屏幕共享       | 独立观众席位、点赞、竞猜、不占玩家席位        |
| AI         | 无法补位，也无法理解牌局   | AI 补位、桌搭子聊天、按牌桌事件互动           |
| 隐私       | 需要交换个人账号或邀请进群 | 房间级身份，散局即走，不要求交换微信          |

微信在熟人关系、离线消息和通知上更强。我们不应该试图替代它，而应该让玩家形成：

> 微信约局，客户端开局；微信聊日常，客户端聊这一局。

## 为什么用我们的连麦

- **一键进房**：邀请链接同时携带房间身份，不需要建群、加好友、发会议号。
- **语音和牌桌同屏**：谁在发言、谁在听、谁掉线、谁是观众、谁被房主禁言，都在同一个房间状态里。
- **游戏事件联动**：回合开始、关键操作、成就解锁和舞台演出可以触发语音提示或派对音效。
- **权限清晰**：房主控制谁可以开麦、谁可以放横幅、谁可以触发舞台；不需要把所有人拉进一个永久群。
- **隐私更轻**：一局结束即可退出，不需要交换个人微信或长期留在群里。
- **跨端入口**：电脑开房，手机浏览器或 iOS 客户端加入；语音能力按平台逐步开放。

需要诚实说明边界：通用语音的稳定性、噪声抑制和跨网络质量，微信 / Discord 更成熟。我们的优势是“游戏内语音”，不是“取代所有语音软件”。网络差时应明确提示并允许退回文字聊天。

## 为什么用我们的聊天

- **消息有上下文**：成就、回合、投票、竞猜、舞台事件都在同一条房间时间线上，回放时可以还原。
- **低门槛表达**：快捷短语、表情、鸡蛋/鲜花/拖鞋、点赞、鼓掌、催更，比打字更快。
- **不冷场**：成就广播、AI 桌搭子和舞台提示让等待、结算和长考阶段也有内容。
- **观众也参与**：观众可以点赞、竞猜、发观众表情，不占玩家席位、不偷看手牌。
- **房间级隐私**：不需要把个人社交账号交给陌生人；房间关闭后聊天自然结束。
- **和游戏状态绑定**：未来可以回复某手牌、某回合、某个成就，而不是在纯文本里丢失上下文。

我们不需要在“日常聊天”上赢微信；只需要在“这一局牌桌内的沟通”上明显更好。

## 社交符号体系

社交符号必须绑定真实状态或事件，不能只是装饰。建议分五层：

### 1. 身份层

| 符号         | 作用                   | 来源                   |
| ------------ | ---------------------- | ---------------------- |
| 头像与座位色 | 快速识别玩家           | 现有头像、座位         |
| 成就徽章     | 展示长期投入与稀有成就 | 成就系统               |
| 称号         | 赛季、连胜、房间 MVP   | 新增，按房间或赛季结算 |
| 房间角色     | 房主、玩家、观众、AI   | 现有房间状态           |
| 连胜 / 段位  | 给长期玩家成长感       | 新增，先做房间级统计   |

### 2. 状态层

| 符号       | 作用                          |
| ---------- | ----------------------------- |
| 准备       | 开局前最关键的等待信号        |
| 思考中     | 让其他人知道不是卡死          |
| 暂离       | 主动离开但不掉线              |
| 离线       | 连接状态，不自动等同托管      |
| AI 托管    | 明确显示当前由 AI 代打        |
| 观众       | 不占席位、不显示私人手牌      |
| 麦克风状态 | 发言、静音、被房主禁言        |
| 网络质量   | 延迟/丢包提示，避免误判操作慢 |

### 3. 表达层

| 符号      | 作用                       | 频率控制          |
| --------- | -------------------------- | ----------------- |
| 快捷短语  | 不需要打字                 | 现有常用语        |
| 表情雨    | 轻量情绪表达               | 每人冷却          |
| 鸡蛋/鲜花 | 现有互动，带舞台粒子       | 现有派对/互动冷却 |
| 点赞/鼓掌 | 对好操作或成就的即时反馈   | 每回合上限        |
| 催更/思考 | 提醒慢速玩家但不冒犯       | 冷却，默认低音量  |
| 投票      | 重开、继续、规则选择       | 房间级，结果可见  |
| 竞猜币    | 观众参与胜负、成就、下一手 | 不改变对局结果    |

### 4. 事件层

| 符号     | 触发                     | 表现                       |
| -------- | ------------------------ | -------------------------- |
| 成就广播 | 史诗/传说/神话成就解锁   | 聊天卡片 + 舞台 + 观众可见 |
| 逆转     | 大幅落后后反超           | 舞台聚光 + 全桌提示        |
| 连胜     | 连续获胜或连续达成条件   | 身份徽章 + 简短舞台        |
| 神操作   | 一炮多杀、连跳、清一色等 | 游戏事件舞台               |
| 安慰     | 被淘汰、被逆转、掉线     | 低优先级、可关闭           |
| 观众喝彩 | 观众点赞/竞猜命中        | 观众席粒子，不打断牌桌     |
| MVP      | 房间结束投票或统计       | 结算页 + 成就墙            |

### 5. 记忆层

- 对局回放时间轴标记成就、舞台和关键互动。
- 房间“最佳时刻”自动截取 3–5 个事件，生成可分享摘要。
- 成就墙展示最近解锁和稀有度，不公开私人统计。
- 赛季/房间统计：胜场、连胜、最常一起玩的人、最常触发的舞台。

## 差异化体验

1. **牌桌会回应**：成就、关键操作和聊天都能触发舞台；AI 桌搭子能根据牌桌内容主动说话。
2. **不用解释就能看懂**：谁在思考、谁掉线、谁在托管、谁在观众席，状态符号直接显示。
3. **每个人都能被看见**：观众有独立身份、点赞和竞猜；结算有 MVP 和最佳时刻。
4. **一局结束不是结束**：回放、成就墙、房间故事和下次邀请把一局变成长期关系。
5. **零门槛进入**：邀请链接、手机浏览器、AI 补位，不需要先建群或安装大型客户端。

## 实施路线

### 第一阶段：低噪音的局内符号

- 准备、思考中、暂离、离线、AI 托管、观众、麦克风状态。
- 点赞/鼓掌、催更/思考、快捷短语冷却。
- 成就卡片与史诗以上舞台已实现；普通/稀有只保留聊天卡片。
- 结算页显示本局成就和最佳操作。

### 第二阶段：房间记忆与观众

- 回放时间轴标记成就、舞台和互动。
- 房间最佳时刻摘要。
- 观众点赞、竞猜、观众席粒子。
- 成就展柜和房间 MVP。

### 第三阶段：AI 桌搭子与长期身份

- LLM 聊天与主动搭话（按 [舞台与 LLM 计划](social-stage-llm-plan.md)）。
- 赛季/连胜/称号。
- 房间故事和可分享战报。

## 指标

- 局内互动率：每局消息、表情、点赞、互动的参与人数。
- 语音加入率与语音留存：进入房间后开启语音的比例。
- 邀请转化率：打开邀请链接后进入房间并完成一局的比例。
- 成就分享率：解锁后广播/展示的比例。
- 观众留存：观众停留时长与竞猜参与率。
- 再来一局率：结算后继续下一局或创建新房间的比例。
- 主观反馈：玩家是否能说出“这个功能微信做不到”的具体场景。

## 风险与控制

- **噪音与骚扰**：默认低频率、冷却、静音、房主权限；成就广播可关闭。
- **隐私**：房间级身份，不公开私人手牌、私聊和完整统计；成就分享由玩家决定。
- **性能**：舞台按稀有度和质量分级；低端设备回退文字/关闭。
- **移动端语音缺口**：先明确平台能力，不承诺手机浏览器完整语音；逐步补齐 iOS / Android。
- **AI 成本与延迟**：LLM 只做聊天和候选选择，超时回退；默认关闭。
- **和微信竞争的心态**：不做通用 IM，不追求替代微信；只把“这一局”做到明显更好。

## 待确认

- 社交符号优先做哪一层：状态层、表达层还是记忆层？
- 语音是否作为下一阶段重点，还是先做文字 + 舞台 + 观众？
- 成就广播默认开启是否合适，还是改为房间创建时选择？
- 是否引入房间 MVP / 赛季称号，还是先做单局最佳时刻？
